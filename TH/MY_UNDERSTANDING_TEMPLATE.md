## Backend

**1. HTTP method แต่ละตัวในแอปของคุณหมายถึงอะไร — GET, POST, PUT or PATCH, และ DELETE? ทำไมเราถึงใช้ method ต่างกัน แทนที่จะใช้ POST สำหรับทุกอย่าง?**

_คำตอบของคุณ:_
เพราะเราไม่ได้จะสร้างข้อมูลใหม่ตลอดเวลาครับ GET ไว้ดึงข้อมูลอย่างเดียว POST ก็ใช้แค่สร้างข้อมูลใหม่ PATCH ก็ใช้อัพเดทข้อมูลตามฟีลด์ที่แก้ไข DELETE ใช้ลบข้อมูลออกจาก Databse

---

**2. `express.json()` คืออะไร และจะเกิดอะไรขึ้นถ้าคุณไม่ใส่มัน?**

_คำตอบของคุณ:_
คือ middleware ที่มากับ express ที่แปลง req body จาก json เป็น js object ถ้าไม่ใส่ express จะไม่รู้ว่าจะแปลงยังไง ทำให้ req.body มีค่าเป็น undefined แล้วจะใช้ HTTP Method ไม่ได้

---

**3. `req.body`, `req.params`, และ `req.query` ต่างกันอย่างไร? ยกตัวอย่างจริงจาก API ของคุณสำหรับแต่ละตัว**

_คำตอบของคุณ:_
req.body คือ object ก้อนใหญ่สุด ที่ส่งมาจาก client ยกตัวอย่างคือ ยิง POST /products จะได้ {name: "Ferrari cap", ...} เป็นต้นครับ
req.params คือตัวแปรใน Url Path ยกตัวอย่าง ตอนยิง PATCH /product/1 จะได้ req.params.id เป็น "1"
req.query คือค่าที่ส่งต่อท้าย URL หลังเครื่องหมาย ? ใช้เพื่อค้นหา หรือกรอก เช่น ยิง GET /product?name=Cap จะได้ req.query.name เป็น Cap

---

**4. HTTP status codes คืออะไร? ระบุรายการ status code ทุกตัวที่คุณใช้ใน API และอธิบายว่าทำไมถึงเลือกใช้ในแต่ละสถานการณ์**

_คำตอบของคุณ:_
เป็น รหัสที่ server บอกกับ client ว่าผลลัทธ์ของ Request เป็นยังไง เช่น 200 คือ OK 404 คือ Not Found

---

**5. middleware คืออะไร? อธิบายด้วยคำพูดของคุณเองว่ามันทำอะไร พร้อมยกตัวอย่าง 1 อย่างจากโค้ดของคุณ**

_คำตอบของคุณ:_

--- คือ function ที่คั่นระหว่าง Request กับ Route Handler ยกตัวเช่น Custom Logger ที่คอย log ทุกครั้งที่มีคนยิงเข้ามา แล้วก็เรียก next() เพื่อปล่อย Request ไปต่อ

**6. ทำไม order ของ middleware ใน Express ถึงสำคัญ? จะเกิดอะไรขึ้นถ้า order ผิด?**

_คำตอบของคุณ:_

--- เพราะ Express ทำงานแบบบนลงล่าง ถ้าสลับลำดับ แบบเขียน app.use(express.json()) หลัง app.use("/", productRouter) req.body ที่เข้ามา จะได้ undefined เพราะยังไม่ได้แปลง json เป็น js object ก่อน

**7. อธิบายทีละขั้นตอนว่าเกิดอะไรขึ้นบน server เมื่อมี POST request ถูกส่งไปที่ `/products`**

_คำตอบของคุณ:_

--- request ส่งไปที่ port 3001 -> วิ่งผ่าน Cors เพื่อให้อนุญาตข้าม Origin -> express.json() แปลง Json เป็น object ใน req.body -> วิ่งผ่าน Logger Middleware -> วิ่งเข้า Router เจอ router.post("/product", ...) -> validation ว่า name, price, quantity มาครบไหม -> ถ้าครบ สร้าง newProduct -> push newProduct เข้า products array -> respond ไป client พร้อม status และ ข้อมูล product ใหม่

**8. CRUD คืออะไร? จับคู่แต่ละ operation กับ HTTP method และ route ที่คุณใช้ใน API**

_คำตอบของคุณ:_

--- CRUD : Create, Read, Update, Delete
จับคู่
Creat: POST /products
Read: GET /products (อ่านทั้งหมด และค้นหา)
Read: GET /products/:id (อ่านชิ้นเดียว)

**9. API ของคุณตอบสนองอย่างไรเมื่อมีอะไรผิดพลาด — เช่น เมื่อ product ตาม ID ที่ระบุไม่มีอยู่จริง?**

## Frontend & Integration

**10. CORS คืออะไร และแก้ปัญหาอะไร? ถ้าไม่ได้ config ไว้บน server ของคุณ คุณจะเห็นอะไรใน browser?**

_คำตอบของคุณ:_

--- Cors เป็นกลไกความปลอดภัยของ browser ไว้แก้กฎ same-origin policy เพื่อให้ frontedn รัน port นึง ส่งไป port นึง ได้ ถ้าไม่ได้ config browser block แล้ว
"Access to fetch at 'http://localhost:3001/products' from origin 'http://localhost:5173' has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present on the requested resource."

**11. แอป React ของคุณ fetch ข้อมูลจาก API ที่ไหน? อธิบายว่า `useEffect` ในโค้ดนั้นทำอะไร และทำไมถึงเรียก fetch ตรง ๆ ใน component body ไม่ได้**

_คำตอบของคุณ:_

--- fetch ข้อมูลใน app.jsx โดย useEffect สั่งให้ fetchProduct() ดึงข้อมูลจาก api แค่ครั้งเดียวตอนเปิดหน้า ถ้า fetch ตรงใน body ก็ infinite loop

**12. API base URL ของคุณถูกกำหนดไว้ที่ไหน และทำไมถึงเลือกเก็บไว้ตรงนั้น แทนที่จะ hardcode ไว้ในทุก fetch call?**

_คำตอบของคุณ:_

--- เขียนไว้ในไฟล์ .env แล้วก็ที่ไม่ hard code เพราะ Single Source of Truth ก็คือ ถ้า server เปลี่ยน port ก็แก้ที่ .env ที่เดียว แล้วก็ ปลอดภัยเพราะแยก config ออกจาก codebase

**13. เลือก action หนึ่งในแอปของคุณ — เช่น การลบ product อธิบายการเดินทางแบบครบวงจร (full round trip): เกิดอะไรขึ้นตั้งแต่ผู้ใช้คลิกปุ่ม ไปจนถึง request ไปถึง server จนถึงหน้าจออัปเดตด้วย list ใหม่**

_คำตอบของคุณ:_

--- user กดปุ่ม delete ใน Table.jsx -> เรียกฟังก์ชั่น deleteProduct(id) -> ส่ง id product ไป App.jsx -> App.jsx ยิง HTTP Request -> Request เข้ามา express ที่ port 3001 -> express ตรวจสอบ router -> วิ่งเข้า roueter.delete(...) -> server หา index ใน array ด้วย .find() และ .spice() ลบ -> server ตอบกลับ client ด้วย status 204 no content

**14. แอปของคุณแสดงอะไรให้ผู้ใช้เห็นระหว่างที่ข้อมูลกำลังโหลด และแสดงอะไรถ้า fetch ล้มเหลว (เช่น server ไม่ได้รันอยู่)? ทำไมเรื่องนี้ถึงสำคัญ?**

## AI Process

ตอบส่วนนี้เฉพาะถ้าคุณ rate ตัวเอง **2 ขึ้นไป** บน AI Code Contribution Scale ด้านบน ถ้า rate ไว้ 0 หรือ 1 ให้เขียน "N/A" ใต้แต่ละคำถาม

**17. ถ้าคุณใช้ AI สร้างโค้ด คุณแบ่งงานออกเป็นขั้นตอนหรือ prompt อย่างไร? ยกตัวอย่าง prompt จริงที่คุณใช้ 1 อัน แทนที่จะเป็น prompt เดียวแบบ "สร้างทั้งแอปให้หน่อย"**

_คำตอบของคุณ:_

--- ก็ให้ช่วยดู requiment แล้ว list มาเป็นลำดับ เพื่อให้เริ่มต้นทำงานได้ง่าย เป็นงานย่อย แล้วก็ค่อยเช็คว่า มีอะไรที่ rubic แจ้งไว้ แต่ฉันยังไม่ได้ทำ ยกตัวอย่างเช่น "สรุป data flow router หน่อย"

**18. อธิบายสิ่งที่ AI tool สร้างให้ 1 อย่างที่คุณเปลี่ยน แก้ไข หรือปฏิเสธ — พร้อมเหตุผลว่าทำไม**

_คำตอบของคุณ:_

--- const url = name ? `${API_URL}?name=${name}` : API_URL; ใน fetchProduct ตอนแรก ฟังก์ชันดึงข้อมูลถูกเขียนให้ยิงไปที่ API_URL ตรงๆ อย่างเดียว ซึ่งทำได้แค่ดึงสินค้าทั้งหมด ตอนเปิดหน้าเว็บ

**19. อธิบาย bug หรือ error จริง ๆ ที่คุณเจอระหว่าง build โปรเจกต์นี้ 1 อย่าง คุณหาสาเหตุที่แท้จริงได้อย่างไร นอกเหนือจากการ copy error ไปถามใน chat?**

_คำตอบของคุณ:_

--- บั๊กเรื่อง Path Prefix ของ Express Router ที่ตอนแรกเขียน router.get("/products") ทั้งๆ ที่ใน index.js มีการ mount ไว้แล้ว ทำให้ Path ซ้ำกลายเป็น /products/products และยิงไม่ติด (404)
ก็ดู Log ที่ Terminal ของ Node และดู Request URL ใน Developer Tools จนเข้าใจว่า Express มีการตัดและต่อคำนำหน้าของ Router อย่างไร

**20. เลือก route (backend) หรือ component (frontend) 1 อันที่ AI ช่วยสร้าง โดยไม่ย้อนกลับไปดู AI chat history อธิบายว่ามันทำอะไรและทำไมถึงทำงาน ด้วยคำพูดของคุณเอง**

_คำตอบของคุณ:_

--- GET /products ในส่วนการค้นหาชื่อ โดยรับ request มาจาก client แล้วดึง name ออกจาก req.query หลังจากนั้นประกาศตัวแปร filteredProducts แล้วเก็บค่าจาก products ที่เป็น mockdata หลังจากนั้นประกาศ if statement แล้วถ้ามี name จะ re assign filteredProducts โดยรับค่าจากตัวมันเองที่ทำการ .filter ข้างในเป็น callback fn รับ parameter มาเป็น object ข้างใน products array แล้วค้นหาว่ามีคำที่รับค่ามาจาก name ด้วย .include โดยแปลงทั้งหมดเป็น พิมพ์เล็ก ซึ่งสุดท้าย ค่าใน filteredProducts ก็จะเป็น object ที่มีชื่อที่ตรงกับคำค้นหาของ users ที่ส่งมาใน request
